# ACE-ECHO 1.0 — Venus 1.0 on Gem5

ACE-ECHO 1.0 provides a Gem5-based development flow for Venus 1.0: compile Venus C/BAS tasks, assemble DAGs, run fast functional and cycle-level simulation, build Scheduler firmware, and compare against an independently run RTL implementation.

## Changes

- Venus1 dependency DMA uses the runtime returned length, including the RTL descriptor width, while declared producer allocation capacity is preserved.
- Inferred capacity metadata is advisory; capacity diagnostics remain visible without rejecting otherwise RTL-compatible cases.
- NR PDCCH receives the complete equalizer output before gathering the demodulator working vectors.
- The platform pins the exact workload implementation used in regression.

## Validation boundaries

- All known output bits match. RTL contains 607,984 unknown bits across the requested return buffers, so the declaration-free full transport comparison is not a complete bit-exact PASS. Unknown bits have not been silently reclassified as padding.
- No independent MATLAB/golden algorithm qualification is asserted. The PDSCH sample CRC question remains separate from simulator agreement.
- Runtime DMT allocation differs from Gem5 static slot reuse. RTL also skips code transfers on a code-CRC hit; the current Gem5 path retains those transfers. After accounting for 82 extra Gem5 code loads, all 3,128 RTL transfers match in ordered direction, Tile address, and length. This does not establish AXI handshake equivalence.
- The L1 contract engine interprets the firmware execution plan and simulates its transfers; it does not execute the full L1 scalar Scheduler CPU.
- RTL and proprietary EDA tools are not distributed. The Venus-custom LLVM compiler is an external prerequisite; ordinary upstream LLVM is insufficient.
